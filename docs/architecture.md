Проект представляет собой корпоративный чат с поддержкой личных и групповых каналов, обмена сообщениями, вложений, реакций и интеграции с корпоративным порталом через JWT.
В качестве серверного фреймворка выбран NestJS. Он предоставляет модульную архитектуру, встроенную поддержку внедрения зависимостей, декораторов и тесную интеграцию с TypeScript.
Основным языком разработки является TypeScript. Статическая типизация позволяет обнаруживать большое количество ошибок ещё на этапе компиляции.
В качестве системы управления базой данных выбрана PostgreSQL. Она поддерживает сложные связи между сущностями, транзакции, внешние ключи и эффективную работу с индексами, что делает её подходящей для хранения сообщений, пользователей, каналов и связей между ними.
Для взаимодействия с базой данных используется Prisma ORM. Prisma обеспечивает типобезопасный доступ к данным, автоматическую генерацию клиента на основе схемы, удобный механизм миграций и значительно сокращает количество шаблонного SQL-кода.
Авторизация пользователей реализована с использованием JWT и библиотеки passport-jwt. Согласно техническому заданию, сервер не занимается выдачей токенов самостоятельно, а принимает JWT, сформированный корпоративным порталом. После проверки подписи и срока действия токена пользователь считается аутентифицированным. Такой подход позволяет отделить процесс аутентификации от бизнес-логики сервера.
Для хранения файлов выбран MinIO — объектное хранилище, совместимое с Amazon S3 API. Использование MinIO позволяет разрабатывать и тестировать систему локально без зависимости от облачных сервисов.
Для контейнеризации приложения используется Docker, а для запуска нескольких сервисов одновременно — Docker Compose. Это позволяет разворачивать базу данных, файловое хранилище, сервер одной командой, обеспечивая одинаковое окружение на всех рабочих станциях разработчиков.
Для автоматической проверки проекта используется GitHub Actions. При каждом изменении кода автоматически устанавливаются зависимости, генерируется Prisma Client и выполняется сборка проекта. Это позволяет обнаруживать ошибки на ранних этапах разработки и гарантирует, что репозиторий всегда находится в работоспособном состоянии.
В результате выбранный стек технологий обеспечивает модульную архитектуру, удобство сопровождения и соответствует современным практикам разработки серверных приложений.
